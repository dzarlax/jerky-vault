Current Behavior

Previous migration state

The existing 2026-05-24 migration plan records completed slices for the adapter, dashboard/app shell, orders, products/recipes, CRUD pages, modals, auth/profile, and wide-screen dashboard checks.

CSS import order

src/pages/_app.tsx imports design-system.css, then batchvault-adapter.css, then components.css. Because components.css loads last, adapter rules sometimes rely on specificity and !important to survive.

Style overlap

components.css and batchvault-adapter.css both define major selectors such as .card, .stat-card, .sidebar, .page-container, .filter-bar, .table, .modal-*, .react-select__*, .profile-*, .order-item-*, .product-card, and .recipe-card.

Docker dev server

The dev compose file runs npm run dev -- -H 0.0.0.0 -p 3000, but previous memory notes mention flaky HMR with repeated webpack.hot-update.json 404s. No polling-related env variables are currently visible in the tracked compose example.

Recommended Approach

Use a narrow "stabilize and document" approach instead of broad refactoring.

  1. Move the adapter import after legacy component styles so adapter rules become the final product-level layer.
  2. Delete adapter overrides that only exist because of the current import order, but keep product-level overrides in the adapter.
  3. Document current BatchVault UI conventions from the code that already exists instead of inventing a new component system.
  4. Add explicit Docker watch polling settings only if live verification shows HMR still misses changes.

This keeps the pass reviewable and avoids mixing QA cleanup with a second redesign.

Desired Behavior

  • Dark mode remains readable and consistent across dashboard, orders, products, recipes, clients, ingredients, prices, profile, auth pages, and representative create/edit modals.
  • The CSS layering is easier to reason about: base tokens first, legacy component definitions second, BatchVault adapter last.
  • The adapter owns product-level decisions: brand colors, dark-mode bridge, app density, sidebar/footer fixes, dashboard/card refinements, modal containment, and mobile overflow fixes.
  • Legacy components.css remains the broad component source during this pass; high-risk selector moves are avoided unless they are trivial and directly reduce duplication.
  • A short durable doc records table, form, modal, card, state, and shell conventions for future BatchVault work.
  • Docker dev-server behavior is verified with a real source edit. If HMR is unreliable, the compose example gets explicit polling env vars and the plan records the result.

Upstream Design-System Candidates

  • Application shell pattern: fixed sidebar, scrollable nav, pinned footer.
  • Dense CRUD table pattern with mobile horizontal scrolling.
  • CRUD modal pattern with constrained viewport height and scrollable body.
  • Operational card pattern: restrained hover, compact metadata, stable mobile columns.
  • React-select visual bridge, documented as implementation guidance rather than design-system JavaScript.
  • App typography preset: system sans headings, compact line heights, no editorial serif base import.

Risks and Edge Cases

  • Changing import order can reveal hidden dependencies on the current cascade. Browser QA is required before calling it safe.
  • Removing !important too aggressively can regress Bootstrap tables, modals, or react-select portals.
  • Docker HMR behavior may depend on Docker Desktop file-watching quirks on Windows, so the result should be documented as environment-specific.
  • Dark-mode QA can tempt broad restyling. This pass should fix clear regressions only.
  • The local ignored docker-compose.dev.yml may contain machine-specific secrets or database URLs and must not be staged.

Rollback Plan

Rollback is a normal git revert of this follow-up branch. If the CSS import order change causes broad visual regressions, revert _app.tsx first and keep only the documentation/HMR findings. If a specific selector cleanup regresses one page, restore that selector from the previous adapter or component stylesheet.
