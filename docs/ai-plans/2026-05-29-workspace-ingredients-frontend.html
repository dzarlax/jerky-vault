Implementation Plan: Workspace Ingredients Frontend

Approval required Frontend repository Backend contract inspected

Date: 2026-05-29. Frontend branch inspected: codex/workspace-ingredients-frontend-plan. Backend branch inspected: codex/workspace-ingredients-strict-mode-plan.

Task Summary

Bring the frontend ingredients and pricing workflow in line with the new workspace-aware backend. The backend now supports workspace resolution through X-Workspace-ID, workspace ingredient membership, and workspace-scoped prices. The frontend already has an initial workspace context and partial page migrations, but the ingredients screen still needs to become a workspace ingredient workbench instead of a lightly modified legacy ingredient table.

Inspected Current State

Backend facts

  • GET /api/workspaces is JWT-only and bootstraps accessible workspaces.
  • Most protected routes run through WorkspaceMiddleware.
  • X-Workspace-ID selects workspace; if absent, backend falls back to personal workspace.
  • GET /api/workspace-ingredients returns active workspace ingredients with nested ingredient and optional latest_price.
  • POST /api/workspace-ingredients links an existing global ingredient to the current workspace.
  • DELETE /api/workspace-ingredients/:id deactivates workspace membership.
  • POST /api/ingredients creates a global ingredient and links it to the current workspace; if the name exists it returns workspace_linked metadata.
  • GET /api/prices and POST /api/prices are workspace-scoped.

Frontend facts

  • WorkspaceProvider fetches /api/workspaces, stores selected workspace per user, and marks it validated in sessionStorage.
  • fetcher sends X-Workspace-ID after workspace validation.
  • Dashboard, clients, recipes, products, orders, prices, and ingredients use workspaceKey in several places.
  • src/pages/ingredients.tsx already fetches /api/workspace-ingredients.
  • AddIngredientModal already searches global ingredients and can add an existing ingredient to the workspace.
  • src/pages/prices.tsx already uses workspace ingredients as the ingredient source.

Current Gaps

  • The ingredients page primary action is still Add Ingredient; the frequent workflow should be Update Price.
  • The page still uses a type dropdown. Prior design discussion chose separate filter axes: ingredient type and price state.
  • There is no price-state filter such as all, missing, current, stale.
  • The table shows latest price but does not expose the expected fast row action for creating a new price.
  • Deactivate is shown as a direct row action; this needs clearer wording and probably confirmation because it archives workspace membership.
  • The add ingredient modal mixes "create new dictionary ingredient" and "add existing to workspace" in one form, but it needs clearer search-first UX and copy.
  • The prices page remains a historical prices table; it can stay, but the ingredients page should launch price creation with the selected ingredient prefilled.
  • Some comments in touched frontend files are Russian. Existing code already has this, but any new code comments should be English.

Desired Behavior

  • The ingredients screen defaults to the current workspace working set, not the global ingredient dictionary.
  • The header uses user-facing language: Add Ingredient for adding to the current workspace working set.
  • Search filters only the current workspace ingredient list.
  • Type and price state are separate filter rows or segmented controls.
  • Each row shows ingredient name, type, latest workspace price, price state, latest price date, and row actions.
  • Row action New Price opens the price modal with the ingredient preselected.
  • Ingredients with no latest price show a clear Add Price action.
  • Removing an ingredient from the workspace is presented as archive/deactivate, not deleting the global ingredient.
  • The add-to-workspace flow searches the global dictionary first, filters out already active workspace ingredients, and falls back to creating a new shared ingredient.

Likely File Changes

  • src/pages/ingredients.tsx - main screen layout, filter axes, price state calculation, row actions, price modal integration.
  • src/components/modal/Ingredients/AddIngredientModal.tsx - clarify search-first workspace add flow and copy.
  • src/components/modal/Prices/AddPriceModal.tsx - support optional preselected ingredient and possibly a tighter "new price for X" mode.
  • src/pages/prices.tsx - align any shared price modal changes and avoid regressions in historical price workflow.
  • src/types/api.ts - refine workspace and workspace ingredient types if backend fields differ from frontend assumptions.
  • locales/*/common.json - add labels for add ingredient, open prices/history, remove from working list, price state filters, stale/current/missing state.
  • src/styles/batchvault-adapter.css or existing style files - scoped table/filter styles for the workbench if existing utilities are insufficient.
  • docs/ai-plans/2026-05-29-workspace-ingredients-frontend.html - update after implementation with actual changes and verification results.

Implementation Steps

  1. Normalize frontend types for Workspace, WorkspaceIngredient, and Price against the inspected backend models.
  2. Refactor AddPriceModal to accept an optional preselected ingredient ID and lock or initialize the ingredient field when launched from an ingredient row.
  3. Update ingredients.tsx state: text search, type filter, price-state filter, selected ingredient for price modal, and pending archive action.
  4. Compute latest price state from workspaceIngredient.latest_price. Start with missing and has price; if "stale" is implemented, use a clearly named constant until backend/config supports a threshold.
  5. Replace the type dropdown with filter chips/segmented controls for type and price state.
  6. Change header action copy to Add Ingredient, while keeping the backend operation as workspace membership creation.
  7. Add row-level New Price/Add Price actions.
  8. Change deactivate wording to archive/remove from workspace and add confirmation if implementation scope allows.
  9. Polish the add-to-workspace modal copy so users understand existing dictionary reuse versus creating a new shared ingredient.
  10. Run typecheck/build/lint checks and manually verify workspace switching, add existing ingredient, create new ingredient, add price, and archive membership.

UX Notes

  • No ingredient IDs in the normal list.
  • No KPI blocks above the table for this pass.
  • Keep the UI dense and operational, not dashboard-like.
  • Use workspace wording carefully in internal code, but prefer user-facing copy such as "ingredients", "working list", and "current space" where possible.
  • Do not show "my ingredient" when the actual scope is workspace.

  • Switch workspace and confirm ingredients list refetches and cache does not show stale workspace data.
  • Search workspace ingredients by name.
  • Filter by type and price state independently.
  • Add an existing global ingredient to the workspace.
  • Create a new ingredient and confirm it appears in the workspace list.
  • Open prices from an ingredient row and confirm the prices page is filtered to that ingredient.
  • Add a price from the prices page and confirm latest price updates after mutate.
  • Archive/deactivate a workspace ingredient and confirm it leaves the active list without deleting the global dictionary entry.
  • Check mobile width for filter wrapping and row action readability.

Risks and Edge Cases

  • Workspace bootstrap race: fetcher only sends the header after validation. Pages must wait for isWorkspaceReady and selected workspace where required.
  • Fallback masking bugs: backend can fall back to personal workspace without a header. Manual QA should confirm selected workspace requests send the header.
  • Stale price definition: there is no inspected backend setting for stale threshold. Any frontend-only stale logic must be explicit and easy to change.
  • Global dictionary duplicates: search-first flow helps but global ingredients.name uniqueness still shapes behavior.
  • Archive semantics: deleting workspace membership is really deactivation. The UI must not imply global deletion.
  • Existing dirty files: frontend repo has untracked AGENTS.md and .superpowers/; implementation should avoid touching unrelated files unless requested.
  • Backend repo dirty file: backend has a modified .claude/settings.local.json; this frontend pass should not modify it.

Rollback Plan

  • Keep backend endpoints unchanged during this frontend pass.
  • Keep the historical /prices page functional while adding row-level navigation from ingredients.
  • If the new workbench layout causes problems, revert only ingredients.tsx, modal changes, locale additions, and scoped CSS from this branch.
  • Do not remove old ingredient or price translation keys in the same pass.

Open Questions

  • What threshold should define a stale price: 30 days, 60 days, custom, or not included in this pass?
  • Should archive/deactivate require a confirmation modal in this first implementation?
  • Should Open prices also prefill the add-price modal when the user clicks Add Price on the prices page?
  • Should adding an ingredient to workspace immediately prompt for first price, or leave that as a separate action on the prices page?

Implementation Update

Implemented 2026-05-29 The production frontend now keeps ingredients and prices as separate screens.

  • /ingredients manages the active workspace ingredient list, with name search, type chips, and price-state chips.
  • Ingredient rows show latest price, price state, and an Open prices action that links to /prices?ingredient_id=....
  • Ingredient row removal is a secondary action with confirmation and deactivates only the workspace membership.
  • /prices reads the ingredient_id query param and filters the workspace price list immediately.
  • The old apply-filters price flow was replaced with immediate client-side filtering and sorting over the fetched workspace prices.
  • The add-ingredient modal now says "search existing ingredients" instead of "global ingredients" in user-facing copy.
  • Translation keys were added for English, Russian, and Serbian; no user-facing copy says "add to workspace".

Checks Run

  • node -e ...JSON.parse...: all three locale JSON files parsed successfully.
  • npm run lint: passed with no warnings or errors. Next still reports the existing config warning that the Next.js ESLint plugin was not detected.
  • npm run build: passed. The project build skips type validation and linting by configuration.
  • npx tsc --noEmit: blocked by pre-existing unrelated type errors in calculator, DonutChart, SelectDropdown, index, orders, and products.
  • npx tsc --noEmit --pretty false | Select-String ...: no type errors were reported for the modified ingredients/prices/modal files.

Known Limitations

  • No stale-price threshold was implemented because the product rule is still open.
  • The prices page filter is client-side over the fetched workspace price list; if price history becomes very large, this should move to a server-backed paginated filter.
  • The add-price modal is not preselected from the query-filtered ingredient yet.
